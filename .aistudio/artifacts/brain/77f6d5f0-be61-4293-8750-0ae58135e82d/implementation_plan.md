# আর্থিক স্বচ্ছতায় রসিদ সফট-ডিলিট ও ভয়েড (Void Receipt) ব্যবস্থাপনা

আর্থিক স্বচ্ছতা ও অডিট ট্রেইল অক্ষুণ্ণ রাখার লক্ষ্যে মাদরাসার ছাত্র ফি এবং অনুদান/যাকাত মডিউলে রসিদ স্থায়ীভাবে মুছে ফেলার (Hard Delete) পরিবর্তে একটি নিরাপদ **"রসিদ বাতিল (Void Receipt)"** ওয়ার্কফ্লো বাস্তবায়ন করা হবে। বাতিলকৃত রসিদগুলো মুছে না গিয়ে লাল "VOID" ব্যাজ ও স্ট্রাইকথ্রু (line-through) সহ সংরক্ষিত থাকবে, স্বয়ংক্রিয়ভাবে মাদরাসার আয় ও ব্যালেন্স থেকে বাদ পড়বে এবং শিক্ষার্থীর বকেয়া পুনর্বহাল হবে।

---

## User Review & Critical Decisions

> [!IMPORTANT]
> ব্যবহারকারীর সাথে ইন্টারঅ্যাক্টিভ প্রশ্নোত্তর পর্বে নিম্নলিখিত মূল সিদ্ধান্তগুলো চূড়ান্ত করা হয়েছে:

- **সিদ্ধান্ত ১ (ব্যালেন্স ও বকেয়া সমন্বয়):** রসিদ বাতিল বা ভয়েড করা হলে তা মোট আয়ের হিসাব ও লাইভ ব্যালেন্স থেকে স্বয়ংক্রিয়ভাবে বাদ যাবে এবং সংশ্লিষ্ট শিক্ষার্থীর বকেয়া (Due Amount) পূর্বে যে অবস্থায় ছিল সেভাবে পুনর্বহাল হবে।
- **সিদ্ধান্ত ২ (মডিউল আওতাভুক্তি):** এই সফট-ডিলিট ও ভয়েড ব্যবস্থাপনা **শিক্ষার্থী ফি আদায় (`fee_payments` / `fees`)** এবং **যাকাত ও সাধারণ অনুদান (`donations`)** উভয় মডিউলের রসিদেই কার্যকর হবে।
- **সিদ্ধান্ত ৩ (পুনরায় সক্রিয়করণ / Unvoid):** ভুলবশত কোনো রসিদ ভয়েড হয়ে গেলে শুধুমাত্র প্রধান অ্যাডমিন (Super Admin) বিশেষ কারণ উল্লেখ করে তা পুনরায় সক্রিয় (Unvoid / Reactivate) করতে পারবেন। সাধারণ ব্যবহারকারী বা অপারেটরদের জন্য এটি লক থাকবে।

## ১. ওভারভিউ ও মূল উদ্দেশ্য (Overview & Core Concept)

### কী সুবিধা যুক্ত হচ্ছে:
- **নো হার্ড ডিলিট (No Hard Delete):** কোনো রসিদ ডাটাবেস থেকে গায়েব হবে না। প্রতিটি আর্থিক লেনদেনের স্বচ্ছ অডিট ইতিহাস রক্ষিত থাকবে।
- **বাতিলকরণ মডাল (Cancellation Modal):** "রসিদ বাতিল করুন" বাটনে ক্লিক করলে একটি মার্জিত পপআপ মডাল আসবে যেখানে বাতিলের কারণ (`cancellation_reason` যেমন: ভুল ছাত্রের নামে এন্ট্রি, ভুল অংক, বা চেক বাউন্স) লিখে নিশ্চিত করতে হবে।
- **ভিজ্যুয়াল ইনডিকেটর:** বাতিলকৃত রসিদের সারিতে লাল **VOID** ব্যাজ, স্ট্রাইকথ্রু টেক্সট (`line-through text-slate-400`), এবং আয়ের সংখ্যায় অপাসিটি হ্রাস পাবে।
- **রসিদ ভিউয়ারে ওয়াটারমার্ক:** বাতিলকৃত রসিদটি দেখতে গেলে প্রিন্ট ভিউ বা স্ক্রিনে আড়াআড়িভাবে বড় লাল **"বাতিল / VOID"** ওয়াটারমার্ক প্রদর্শিত হবে যাতে কেউ অবৈধভাবে তা পুনরায় ব্যবহার করতে না পারে।

## ২. ইউজার এক্সপেরিয়েন্স ও ইন্টারফেস ডিজাইন (UX & Visual Design)

### মূল ইন্টারঅ্যাকশন ফ্লো:

```
[রসিদ তালিকা]
      │
      ▼ (অ্যাকশন কলামে "বাতিল করুন" বাটনে ক্লিক)
[বাতিলকরণ নিশ্চিতকরণ মডাল]
      │  ├─ রসিদ নং, তারিখ ও টাকার অংক প্রদর্শন
      │  ├─ বাতিলের সুনির্দিষ্ট কারণ লেখার ইনপুট (বাধ্যতামূলক)
      │  └─ "নিশ্চিত বাতিল করুন" (লাল বোতাম)
      ▼
[সার্ভার অ্যাকশন: voidPayment / voidDonation]
      │  ├─ স্ট্যাটাস 'VOID' ও cancellation_reason সেভ
      │  ├─ ক্যাশ/ব্যাংক ব্যালেন্স ও রিপোর্ট সমন্বয়
      │  └─ বকেয়া ফি পুনর্স্থাপন (Rollback Due)
      ▼
[তালিকায় লাইভ আপডেট]
      └─ সারিতে লাল VOID ব্যাজ, হালকা স্ট্রাইকথ্রু টেক্সট ও ডিটেইলস পপওভার
```

### ভিজ্যুয়াল থিম ও স্টাইলিং নির্দেশিকা:
- **VOID স্ট্যাটাস ব্যাজ:** শান্ত কিন্তু স্পষ্ট লাল ট্যাগ `bg-rose-50 text-rose-700 border border-rose-200 text-xs font-bold font-mono px-2 py-0.5 rounded-md`।
- **সারির স্টাইলিং:** বাতিলকৃত রসিদের বিবরণী টেক্সটে `line-through opacity-70 text-slate-400` এবং ব্যাকগ্রাউন্ডে অতি সূক্ষ্ম হালকা স্ট্রাইপ বা টিন্ট `bg-rose-50/20`।
- **প্রিন্ট ভিউ ও রসিদ ওয়াটারমার্ক:** CSS ডায়াগোনাল রোটেটেড টেক্সট (`rotate-[-35deg] text-rose-600/20 text-6xl font-black border-4 border-rose-600/30`)।
- **আন-ভয়েড অপশন:** শুধুমাত্র অনুমোদিত প্রধান এডমিনদের জন্য ড্রপডাউনে "পুনরায় সক্রিয় করুন" অপশন থাকবে।

## ৩. প্রযুক্তিগত স্থাপত্য ও ডাটা স্ট্রাকচার (Technical Architecture)

```
┌────────────────────────────────────────────────────────┐
│                   Frontend UI Layer                    │
│ ┌───────────────────────────┐ ┌──────────────────────┐ │
│ │ /accounting/payments      │ │ /zakat/collection    │ │
│ │ (Student Fee Receipts)    │ │ (Donation Receipts)  │ │
│ └─────────────┬─────────────┘ └──────────┬───────────┘ │
└───────────────┼──────────────────────────┼─────────────┘
                ▼                          ▼
┌────────────────────────────────────────────────────────┐
│                   Server Actions                       │
│ ┌───────────────────────────┐ ┌──────────────────────┐ │
│ │ voidFeePayment()          │ │ voidDonationReceipt()│ │
│ │ unvoidFeePayment()        │ │ unvoidDonation()     │ │
│ └─────────────┬─────────────┘ └──────────┬───────────┘ │
└───────────────┼──────────────────────────┼─────────────┘
                ▼                          ▼
┌────────────────────────────────────────────────────────┐
│               Data Persistence & Rollback              │
│ ├─ Update status to 'VOID', set voided_at & reason     │
│ ├─ Rollback student_fees paid_amount & recalculate due │
│ ├─ Exclude VOID from getUnifiedIncomeHistory & Reports │
│ └─ Write immutable audit log to fee_audit_logs         │
└────────────────────────────────────────────────────────┘
```

### ডাটা মডেল ফিল্ডসমূহ:
1. `status`: `"COMPLETED" | "VOID" | "REVERSED"`
2. `cancellation_reason`: string (বাতিলের কারণ)
3. `voided_at`: ISO timestamp (বাতিলের সময়)
4. `voided_by`: string (যে অ্যাডমিন বাতিল করেছেন)

## ৪. বাস্তবায়নের ধাপসমূহ (Implementation Steps)

1. **ব্যাকএন্ড লজিক (`app/actions/fee-management.ts` ও `app/actions/zakat.ts`):**
   - `voidFeePayment(paymentId, reason)` তৈরি করা যা রসিদ মুছে না ফেলে স্ট্যাটাস `VOID` করবে, বকেয়া রিভার্স করবে এবং অডিট লগ রাখবে।
   - `unvoidFeePayment(paymentId, reason)` তৈরি করা (শুধুমাত্র প্রধান এডমিনের জন্য)।
   - অনুদানের জন্য `voidDonationReceipt(donationId, reason)` তৈরি করা যা ডোনেশন টেবিলে স্ট্যাটাস `VOID` এবং বাতিলের কারণ সংরক্ষণ করবে।
   - সকল রিপোর্ট (`getAccountingReport`, `getUnifiedIncomeHistory`, `getZakatReportStats`) থেকে `VOID` রসিদের টাকা বাদ দেওয়া নিশ্চিত করা।

2. **ইউআই মডাল ও বোতাম পরিবর্তন (`PaymentsClient.tsx` ও `CollectionClient.tsx`):**
   - ডিলিট (Trash) বাটন সম্পূর্ণ অপসারণ করে তার স্থলে "বাতিল করুন (Void)" বাটন দেওয়া।
   - একটি মার্জিত `VoidReceiptModal` কম্পোনেন্ট যুক্ত করা যাতে বাতিলের কারণ টাইপ করার টেক্সটবক্স এবং কনফার্মেশন বোতাম থাকবে।
   - রসিদের তালিকায় `p.status === "VOID"` হলে লাল ব্যাজ, স্ট্রাইকথ্রু এবং টুলটিপ/পপওভারে বাতিলের কারণ ও তারিখ প্রদর্শন।

3. **মানি রিসিট প্রিন্ট ভিউ (`ReceiptModal` / `/receipt` পেজ):**
   - ভয়েড হওয়া রসিদে ডায়াগোনাল "বাতিল / VOID" ওয়াটারমার্ক রেন্ডার করা।

# যাকাত ও অনুদান সংগ্রহে দাতা আইডি (UUID) সামঞ্জস্য ও সমাধান বাস্তবায়ন পরিকল্পনা

যাকাত ও অনুদান সংগ্রহ মডিউলে তালিকাভুক্ত দাতা (যেমন: সাদেকুল ইসলাম) নির্বাচন করে অনুদান গ্রহণ ও রসিদ তৈরি করতে গেলে PostgreSQL ডাটাবেজে `invalid input syntax for type uuid: "donor_..."` ত্রুটি দেখা যায়। ব্যবহারকারীর নিশ্চিত সিদ্ধান্তের ভিত্তিতে **সকল দাতার টেক্সট আইডি স্বয়ংক্রিয়ভাবে স্ট্যান্ডার্ড UUID-তে সিঙ্ক ও রূপান্তর** করা হবে এবং **ভবিষ্যতে সকল দাতা নিবন্ধনে সরাসরি স্ট্যান্ডার্ড UUID ব্যবহার** নিশ্চিত করা হবে।

---

## ১. ইউজার রিভিউ ও নিশ্চিত সিদ্ধান্তসমূহ

> [!IMPORTANT]
> ব্যবহারকারীর সাথে আলোচনা করে নিম্নোক্ত দুটি মূল সিদ্ধান্ত চূড়ান্ত করা হয়েছে:

- **সিদ্ধান্ত ১ (পূর্বের টেক্সট আইডি রূপান্তর):**
  - কেন্দ্রীয় দাতা রেজিস্টার (`meta.life_member_donors`) ও মেটাডাটাতে ইতিপূর্বে সংরক্ষিত যে সকল দাতার আইডি টেক্সট ফরম্যাটে রয়েছে (যেমন: `donor_1792128444291_ll4n`), সেগুলোকে ব্যাকএন্ডে স্বয়ংক্রিয়ভাবে ডাটাবেজের স্ট্যান্ডার্ড `UUID`-তে রূপান্তর এবং `donors` টেবিলের সাথে সিঙ্ক করে নেওয়া হবে।
  - এর ফলে তালিকা থেকে যেকোনো দাতা নির্বাচন করে অনুদান গ্রহণ বা রসিদ তৈরিতে কোনো ডাটাবেজ টাইপ মিসম্যাচ হবে না।

- **সিদ্ধান্ত ২ (ভবিষ্যতে নতুন দাতা নিবন্ধন):**
  - কেন্দ্রীয় দাতা রেজিস্টার, আজীবন সদস্য, মাসিক দাতা ও যাকাত অনুদান—উভয় জায়গায় নতুন দাতা যোগ করার সময় সরাসরি স্ট্যান্ডার্ড `UUID` (`crypto.randomUUID()`) জেনারেট করে ডাটাবেজ ও মেটাডাটাতে সংরক্ষণ করা হবে। টেক্সট প্রিফিক্সড আইডি আর জেনারেট করা হবে না।

## ২. প্রযুক্তিগত কারণ ও স্থাপত্য বিশ্লেষণ (Root Cause & Architecture)

### মূল কারণ বিশ্লেষণ:
1. **ডাটাবেজ কলাম টাইপ:** PostgreSQL `donations` টেবিলের `donor_id` কলামটি একটি ফরেন কি হিসেবে কঠোর `UUID` টাইপ।
2. **টেক্সট আইডি জেনারেশন:** `app/actions/fundraising.ts`-এর `saveLifeMemberDonor`-এ পূর্বে নতুন দাতা এন্ট্রিতে `donor_${Date.now()}_${random}` ফরম্যাটের টেক্সট আইডি তৈরি হতো।
3. **অনুপস্থিত ডাটাবেজ রেকর্ড:** এই টেক্সট আইডির কারণে `adminClient.from("donors").upsert(...)` ডাটাবেজে ফেইল করতো এবং দাতা কেবল মেটাডাটাতে থেকে যেত। পরবর্তীতে কালেকশন ফর্মে ওই দাতা সিলেক্ট করে `addDonation`-এ পাঠালে `donations.insert({ donor_id: "donor_..." })` কল করার সময় ডাটাবেজ `invalid input syntax for type uuid` ত্রুটি দিত।

### প্রস্তাবিত সমাধান আর্কিটেকচার:

```
[Collection Form / Selected Donor]
       │
       ▼ (Sends donor_id: "donor_..." or UUID)
┌────────────────────────────────────────────────────────┐
│  Server Action: addDonation() in app/actions/zakat.ts  │
│                                                        │
│  1. Check isUuid(donor_id)                             │
│     ├─ Valid UUID: Proceed directly                    │
│     └─ Non-UUID ("donor_..."):                         │
│          a. Lookup donor in donors table by phone/name │
│          b. If not present, insert into donors table   │
│             -> gets official UUID                      │
│          c. Update meta.life_member_donors with UUID   │
│          d. Use resolved UUID for donations.insert()   │
│                                                        │
│  2. Safe DB Insertion with Fallback                     │
│     └─ If any FK error, safely record note & recover   │
└────────────────────────────────────────────────────────┘
       │
       ▼
┌────────────────────────────────────────────────────────┐
│  Central Donor Action: saveLifeMemberDonor()            │
│  └─ Generate standard crypto.randomUUID() for new      │
│     donors across both metadata and donors table       │
└────────────────────────────────────────────────────────┘
       │
       ▼
┌────────────────────────────────────────────────────────┐
│  Query Sync: getDonors() in zakat.ts & fundraising.ts  │
│  └─ Auto-heal legacy text IDs to UUIDs on load         │
└────────────────────────────────────────────────────────┘
```

## ৩. বাস্তবায়নের ধাপসমূহ (Implementation Steps)

1. **`addDonation` ফাংশনে বুদ্ধিমান দাতা রেজোলিউশন ও সেইফগার্ড (`app/actions/zakat.ts`):**
   - কালেকশন থেকে আসা `donor_id` যদি ভ্যালিড UUID না হয় (যেমন `donor_1792128444291_ll4n`), তাহলে স্বয়ংক্রিয়ভাবে মেটাডাটা ও `donors` টেবিল যাচাই করে সঠিক UUID শনাক্ত করা।
   - যদি `donors` টেবিলে এখনো রেকর্ড না থাকে, তৎক্ষণাৎ দাতার নাম, ফোন ও ঠিকানা সহ `donors` টেবিলে ইনসার্ট করে নতুন জেনারেটেড UUID নিয়ে অনুদান সফলভাবে সম্পন্ন করা।
   - অনুদান ইনসার্টে যেকোনো অপ্রত্যাশিত টাইপ/এফকে এরর প্রতিরোধে সেইফ ফলব্যাক রাখা।

2. **কেন্দ্রীয় দাতা রেজিস্টারে স্ট্যান্ডার্ড UUID জেনারেশন (`app/actions/fundraising.ts`):**
   - `saveLifeMemberDonor`-এ নতুন দাতার জন্য `donor_${Date.now()}_...` এর বদলে `crypto.randomUUID()` ব্যবহার করা।
   - `donors` টেবিলে আপসার্ট অপারেশন নিশ্চিত করা।

3. **বিদ্যমান দাতাদের স্বয়ংক্রিয় হিলিং ও সিঙ্ক (`app/actions/zakat.ts` ও `getDonors`):**
   - `getDonors()` ফাংশনে মেটাডাটা থেকে লোড হওয়া দাতাদের মধ্যে যেগুলোর আইডি টেক্সট ফরম্যাটে রয়েছে, সেগুলোকে ডিবি দাতাদের সাথে মিলিয়ে বৈধ UUID প্রদান করা।

4. **সদস্য পেমেন্ট ও সাবস্ক্রিপশন সুরক্ষা (`saveDonorSubscriptionPayment`):**
   - মাসিক দাতা বা আজীবন সদস্য চাঁদা কালেকশনেও `donor_id` ভ্যালিড UUID হিসেবে রূপান্তর নিশ্চিত করা, যাতে অনুদান টেবিলে স্বয়ংক্রিয় ট্র্যাকিং অক্ষুণ্ণ থাকে।
